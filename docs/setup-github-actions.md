# GitHub Actions Setup

GitHub Actions runs the pipeline automatically twice per day. No server needed.

---

## How it works

The workflow file at `.github/workflows/outreach.yml` is triggered:
- **07:23 UTC** — primary run (weekdays)
- **11:47 UTC** — backup run (in case GitHub skips the primary; idempotency check prevents double-sending)
- **Manual trigger** — via the Actions tab in GitHub with a `mode` selector

Each run:
1. Checks out the repo
2. Installs Python dependencies with `uv` (fast)
3. Writes Firebase and Gmail credentials from secrets to disk
4. Runs `step6_send_emails.py` (sends emails)
5. Runs `step_summary.py` (sends daily report email)
6. Cleans up credential files

## Step 1: Push your repo to GitHub

```bash
git init
git remote add origin https://github.com/your-org/your-repo.git
git add .
git commit -m "Initial commit"
git push -u origin main
```

Make sure `.gitignore` excludes `pipeline/token.json`, `pipeline/credentials.json`, `pipeline/firebase-service-account.json`, and `.env`.

---

## Step 2: Add secrets

Go to your GitHub repo → **Settings → Secrets and variables → Actions → New repository secret**.

Add each of these:

### `FIREBASE_SERVICE_ACCOUNT`
Full JSON content of `pipeline/firebase-service-account.json`.

```bash
cat pipeline/firebase-service-account.json
```

### `GMAIL_TOKEN_JSON`
Full JSON content of `pipeline/token.json` (generated by `python gmail_auth.py`).

```bash
cat pipeline/token.json
```

### `SENDER_EMAIL`
The Gmail address used for sending (e.g. `you@yourdomain.com`).

### `TRACKING_BASE_URL`
Your Cloudflare Pages URL (e.g. `https://your-project.pages.dev`).

### `NOTIFY_EMAIL`
Where to receive daily summaries and reply approval requests.

### `GEMINI_API_KEY` (optional)
Only needed if you run `step7_ai_replies.py`. Get a free key at [aistudio.google.com](https://aistudio.google.com).

---

## Step 3: Verify

After pushing, go to **Actions** in your GitHub repo. You should see the workflow listed. Click **Run workflow** to trigger a manual test run with `mode: dry-run`.

## Customizing the schedule

Edit `.github/workflows/outreach.yml`:

```yaml
on:
  schedule:
    - cron: '23 7 * * 1-5'   # weekdays 07:23 UTC
    - cron: '47 11 * * 1-5'  # backup run
```

Cron syntax: `minute hour day-of-month month day-of-week`

> GitHub Actions cron runs on UTC time.

---

## Manual trigger options

From the **Actions** tab → select the workflow → **Run workflow**:

| Mode | What it does |
|------|---|
| `both` | Runs step6 + step7 (default) |
| `step6-only` | Sends emails only |
| `step7-only` | AI reply handler only |
| `dry-run` | Prints what would be sent without sending |

## Adding a new campaign to the workflow

To run step6 for a custom campaign, add a new step in `outreach.yml`:

```yaml
- name: Step 6 — My campaign
  if: ${{ github.event.inputs.mode != 'step7-only' && github.event.inputs.mode != 'dry-run' }}
  env:
    SENDER_EMAIL:      ${{ secrets.SENDER_EMAIL }}
    TRACKING_BASE_URL: ${{ secrets.TRACKING_BASE_URL }}
  run: |
    cd pipeline
    python step6_send_emails.py --campaign my_campaign_name
```

## Secret rotation

If you refresh your Gmail token (e.g. after revocation), update `GMAIL_TOKEN_JSON` in GitHub secrets:

1. Run `python gmail_auth.py` locally to get a new `token.json`
2. Go to GitHub → Settings → Secrets → `GMAIL_TOKEN_JSON` → Update
3. Paste the new JSON content

## Troubleshooting

**Workflow not running on schedule**
GitHub may skip runs if the repo has no activity for 60 days. Trigger manually to wake it up, or push a small commit.

**"firebase-service-account.json not found"**
The `FIREBASE_SERVICE_ACCOUNT` secret is missing or malformed. Verify it contains valid JSON.

**"invalid_grant" in Gmail logs**
The OAuth token expired. Re-run `python gmail_auth.py` and update `GMAIL_TOKEN_JSON`.
